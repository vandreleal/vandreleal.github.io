Audit Scripts for a Design System

May 13, 2026 · 3 min read

A design system I work on accumulated a style guide that lived in a contributor doc: story naming, MDX page structure, import discipline, API surface stability, design-token discipline. Contributors had to remember the rules; reviewers had to enforce them by hand. I turned the rules into a suite of audit scripts behind one umbrella command. They block PRs that drift.

The umbrella

A single command runs every audit in parallel. Each subprocess has measurable startup overhead, and running them sequentially compounds that quickly. The parallel runner fans them out, buffers stdout and stderr per check, and replays the output in canonical order so the log stays deterministic regardless of completion order.

Each audit is also runnable on its own. The umbrella command takes a subcommand for a single check, plus flags for audits that need an intentional “regenerate baseline” path, like the API surface snapshot.

The categories

Audits group by what they protect, not by what they run.

Story shape. Every component ships its stories file and docs page in the expected shape. Compound components declare their sub-shapes in story meta so the docs panel renders one props table per sub-shape. No prop spreading on the components that count as stable surface.

Test coverage. Every body-declared prop on an exported props type has at least one positive type test. Every stable component has a colocated property test. Interactive elements get keyboard exercise in their play function.

Public contract. A generated snapshot of the public API surface diffs against the committed baseline. Every body-declared prop carries a JSDoc comment so the docs panel renders descriptions, not just types.

Codebase hygiene. No relative imports inside the design-system root. No hardcoded colors or pixel literals inside component CSS. Every stable component ships a Figma Code Connect file so it surfaces in Figma’s dev-mode panel.

The categories matter more than the individual scripts. New audits get sorted into the same four buckets, and the umbrella stays a flat list rather than a taxonomy.

What I learned

A general-purpose linter does not know about story exports, MDX structure, property-test colocation, or Figma mappings. Each script is short because the rule is short. The umbrella is the only thing that ties them together, and it stays short too because every script is the same shape: walk the design system, find violations, fail with the list. Adding another check is one file and one entry in the canonical step list.

The leverage is not in the scripts. It is in what reviewers stopped doing. Story shape, import discipline, token usage: none of those need eyes anymore. Contributors get the feedback in CI in seconds instead of waiting on a review round. New contributors onboard against what the umbrella enforces, not what the contributor doc happens to mention. Code review stays for the parts that actually need judgment.
