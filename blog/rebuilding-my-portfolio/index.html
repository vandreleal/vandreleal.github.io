Rebuilding my personal site

May 23, 2026 · 3 min read

I rewrote my personal site. The constraint was that every route had to score well on performance, accessibility, best practices, and SEO, and that the visual treatment could not soften to get there. The result is a small static site with a few interactive pieces, an animated backdrop that opts out under reduced motion, and a documented design system.

Static-first with no client framework

The site is mostly text, with a few decorative pieces. A static-first framework is the right shape: every component renders to HTML by default, and the only interactive code that ships is what each page explicitly mounts. An earlier pass used a thin client framework as the wrapper around the heavy bits, a rotating globe and a WebGL backdrop. The wrapper was doing nothing. The actual work lived in non-framework libraries; the wrapper just mounted them. Stripping the framework removed about ten kilobytes gzipped of runtime that no UI was using.

The interactive pieces now mount through plain <script> blocks. Each gates itself: the globe defers until the hero scrolls into view through an IntersectionObserver, the WebGL backdrop checks prefers-reduced-motion and dynamic-imports its implementation only when motion is allowed. The principle survived the framework swap: not “load this as fast as possible” but “should this be loading for this user at all”.

Reduced motion as a real signal

The site has a heavy WebGL backdrop. For users with prefers-reduced-motion, the runtime never loads. The implementation chunk lives behind a dynamic import gated by matchMedia, and the cohort that opted out pays zero bytes for what they will never see. The same logic runs through the rest of the site: every animation has a reduced-motion branch, gated at the highest level the asset graph allows.

Build-time over runtime

Open Graph images, structured metadata, the RSS feed, the sitemap, image variants, and the audit that gates each deploy all happen at build. No headless browser in the pipeline, no fonts to install at deploy time, no first-request cold start. There is also a /system page that lists every color, font, and motion curve in use, read from the same token source as the rest of the site, so the documentation does not drift from the implementation.

A page for the music

There is a /music page that lists tracks I keep nearby: what is on rotation, the all-time list, favorite mix compilations, and a separate cut of Brazilian songs from home. The data is a flat file; the rendering is the same Section primitive that drives the rest of the site.

What I cut

The client framework that was wrapping canvas mounts and earning nothing back. Hydration that would never be seen. Compatibility shims for tools I do not use. Animations that would run for users who asked them not to. Convenience layers that earn their weight on a different shape of project. The site is small in absolute terms, builds in three seconds, and audits in under a minute.
