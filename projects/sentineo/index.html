SentiNEO

Web app that visualizes near-Earth objects and NASA's Astronomy Picture of the Day using the NeoWs and APOD APIs.

Case study

Visualizes the asteroids passing close to Earth this week, plus NASA's Astronomy Picture of the Day. Two data feeds, one quiet page. Runs on Next.js, lives at sentineo.app.

Premise

NASA publishes two underused public APIs: NeoWs, which publishes close approaches of near-Earth objects, and APOD, which serves a daily curated image with a working astronomer's annotation. Almost no consumer-facing apps surface either. SentiNEO combines them into a single page focused on the next seven days of approaches.

The data

NeoWs returns close approaches as a list with absolute magnitude, estimated diameter ranges, miss distance in lunar units and kilometers, and relative velocity. The feed is updated regularly by JPL, so the upcoming pass for any given day is current.

APOD returns a single image or video per day with a curated description. The endpoint is stable enough to use as a background without a fallback.

Diameter is reported as a min/max range because most asteroid sizes are inferred from absolute magnitude assuming an albedo, and that assumption has wide error bars. The page shows both bounds rather than a midpoint to avoid implying false precision.

Miss distance is reported in two units in the same payload: kilometers for absolute scale, lunar distances for human intuition. One lunar distance is roughly 384,400 km, the average Earth-Moon center-to-center distance. The dual reporting is in the API itself, not a SentiNEO addition.

How it works

Each visit pulls the next several days of close approaches and the day's APOD entry. The list shows size, miss distance, and approach date for each object, with the APOD image sitting behind them as visual context. The UI is built on Geist UI so component work stays minimal and engineering time concentrates on the data layer.

Data fetching happens server-side rather than in the browser. That returns a fully rendered list on first paint and lets a CDN cache the response without coordinating with the client. NASA's API rate limits make caching the natural default.

The list rows are static after first paint. There is no client-side filtering or sorting because seven days of approaches is a small enough set that scanning beats interaction.
